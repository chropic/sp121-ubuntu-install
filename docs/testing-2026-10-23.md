# On-device testing: 23 October 2026

The Surface Pro 12in is running **7.3.0-sp12-v7.3-platform** on Ubuntu
26.04.1 LTS. This is the project's main kernel and sole maintained version.
Boot, display, input, audio, sensors, Bluetooth audio and both USB-C video outputs
have on-device results below. Suspend resumes, with logged errors and slow Wi-Fi
reconnection. Battery/performance measurements remain separate follow-up work.

These results cover the `7.3-improvements` sources at `babd4aa` and the installed
payload audited during this session. Recheck live state before maintenance.
The [sanitized evidence record](../kernel/experiments/performance-power/on-device-2026-10-23.json)
contains the supporting observations. Historical v7.3 build and validation records describe
earlier tests and are preserved separately.

## Suspend: functional resumes, unresolved errors

Three short manual **deep** suspend/resume cycles completed in the same 7.3
boot. The operator reported working display, keyboard, touchpad and touchscreen
after each cycle; Wi-Fi took time to reconnect. Measured suspended time was
about 18.1 seconds for the first cycle and 44.6 seconds combined for the next two.
These are short functional checks, not endurance or battery tests.

Every cycle logged both:

- Touchscreen `i2c_hid` resume error `-6`.
- Wi-Fi PCIe controller `1c08000.pcie` timeout waiting for L2 entry.

The touchscreen error also appeared in two earlier 7.2 cycles. The PCIe timeout
was absent from those two inspected cycles, but conditions were not controlled;
a 7.3 regression is **unconfirmed**.

NetworkManager completed reconnection about **22.1 seconds** after the first
kernel-reported resume and **16.1 seconds** after the third. The second cycle
was suspended again before IP configuration finished, so it has no completed
reconnection measurement. A subsequent trial must wait for full connectivity
before suspending again and use the same network/power conditions on both kernels.

Do not describe these results as a clean suspend pass. Longer controlled trials,
wake-source checks and suspend energy measurement remain pending. Mixed awake
and suspend battery readings do not establish energy savings.

## Clock and remaining diagnostics

After the 7.3 cold boot, the **Surface RTC** was selected for boot-time clock
initialization and agreed with an independent UTC check within roughly two
seconds of call latency. The PMIC RTC read approximately six hours behind.
Identify clocks by name: their `rtc0`/`rtc1` numbering changed between boots.
No clock writes were performed.

Chrony was active, while `timedatectl` reported NTP enabled but unsynchronized.
One Surface RTC date read returned no value, then subsequent reads worked; no
errno was captured and no corresponding EC error was found. The cause remains
unknown. UFS RPMB registration and `qcom-apm` command timeout messages also remain
unresolved.

Built-in speaker playback, intelligible microphone recording/playback and both
physical volume buttons passed operator checks on 7.3. The test restored the
original output volume. The recording stays private on the device.

The first recording attempt produced a valid 5.23-second WAV, but the harness
rejected the recorder's exit code after interrupting it. Testing resumed using
that recording; future captures use an exact sample count. This harness error
was not evidence of failed microphone hardware.

## What to test next

1. Finish repeated 7.3 warm reboots. The user canceled the proposed 7.2 rollback
   test and selected 7.3 as the sole maintained/default target. Retained historical
   recovery files are not a second maintained line.
2. Diagnose suspend on 7.3 with controlled conditions and complete network
   activation between cycles. Historical 7.2 logs remain comparison evidence;
   no new 7.2 testing is planned.
3. Investigate the missing HDMI/DP audio route before monitor-speaker playback;
   then test sustained Bluetooth playback,
   reconnection and post-suspend behavior.
   Validate application inking separately from the observed pen input events.
   Confirm desktop auto-rotation/brightness separately from the sensor events.
4. Perform sustained GPU/CPU workload and thermal checks, then longer unplugged
   suspend tests with pre/post energy, elapsed time and wake reasons.
5. Freeze workload inputs, versions, conditions, policy ownership and latency
   instrumentation before performance/power comparisons. Require at least three
   interleaved baseline/candidate pairs per scenario using the
   [experiment guide](../kernel/experiments/performance-power/README.md).

No policy experiments or energy acceptance occurred. By subsequent user direction,
7.3 platform is now the default build and installed-system target; that selection
does not establish a release-tested installer. Cameras remain intentionally disabled in
the platform profile; camera enablement, charge-limit experiments and hibernation
are outside this testing scope. Ubuntu upgrade compatibility is a separate review.
